# 隐私说明与部署者责任

Open Lottery 可以收集中奖联系所需的私密联系方式。仓库维护者无法替部署者决定合法依据、告知文本、保存期限或跨境处理方式；生产部署者必须根据所在地法律和活动规则完成这些工作。

## 数据分类

公开数据包括活动时间、参与总数、公开参与 ID、脱敏中奖昵称、奖项、种子承诺、开奖后种子和候选清单。

私密数据包括用户 ID、源会话 ID、联系方式、原始 session/token、CSRF hash、开奖前私有种子以及任何数据库导出。

安全运行数据还包括请求频率计数。主站按动作选择请求 IP 或活动 session 摘要，并在数据库外用对应网关密钥做 HMAC；数据库只保存不可直接还原的 64 位摘要、动作、窗口和次数，最长约 48 小时，不保存原始 IP。

## 当前保护

- `contact_type` 和 `contact_value` 位于启用 RLS 的私有表；
- `main-site` 网关在写入 RPC 前使用 AES-256-GCM 加密，`contact_value` 只保存版本化密文信封；
- 活动 ID 和联系方式类型作为附加认证信息，防止密文被跨活动或跨类型搬移；
- `PUBLIC`、`anon`、`authenticated` 无表权限；
- `service_role` 也不能直接读取 `contact_value`，必须调用会写入审计的单条读取 RPC；
- 普通浏览器 API 不查询联系方式；
- provider 返回值在本站再次经过公开字段白名单；
- 联系方式不会进入候选清单、参与编号或中奖公示；
- 测试断言会检查联系方式没有进入浏览器响应。

## 密钥边界

加密 keyring 只配置在主站服务端，不进入独立活动站、浏览器、数据库或公开构建。数据库管理员、service role 和备份读取者只能看到密文信封。配置缺失时参与请求会失败，不会回退到明文落库。

当前主站报名网关使用对称密钥完成加密，因此其运行进程理论上也具备解密能力。主站只向当前活动显式持有 `contact_read` capability 的兑奖人员提供单条读取，隐私删除另需 `contact_purge`；全局 `super_admin` 不会自动获得联系方式权限。每次读取先由数据库写入不可修改的用途审计，页面在 60 秒后或切到后台时隐藏明文，并且不提供批量明文导出。更严格的部署应使用支持仅加密权限的 KMS，并把解密收口到独立兑奖服务。格式、轮换与旧明文升级见 [联系方式加密](CONTACT_ENCRYPTION.md)。

准备与开奖的操作审计只保存活动 ID、管理员 actor、动作和时间，不保存私有 seed、联系方式或 Beacon 响应正文。活动站不持有 draw seed，也不提供长期 Bearer 运营路由。

## 当前限制

迁移 162 为活动设置明确的 `contact_retention_until`，模板默认是计划开奖后 30 天。到期后读取 RPC 立即拒绝访问，每日清理任务会将该活动全部 `contact_value` 设为 `NULL`，同时保留参与编号、公开复算材料和中奖记录。提前删除请求也只清除指定中奖记录的密文。

独立兑奖 capability 已实现，但备份过期验证尚未实现。在线数据库删除不会追溯删除旧备份、WAL、只读副本或人工导出，部署者必须让这些副本按单独周期过期。

## 建议保留策略

部署者应在活动规则中明确具体期限。一个可执行的默认策略是：

1. 开放参与前把 `contact_retention_until` 改成活动规则承诺的准确时间；
2. 活动结束前只允许领奖运营人员通过单条审计入口访问；
3. 发奖完成或收到删除请求时，可提前清除单条中奖联系方式；
4. 每日检查 `/api/summer-lottery-contact-retention` 任务成功记录；
5. 数据库备份按单独周期过期，不无限保留；
6. 定期核对 `summer_lottery_contact_access_audit`，但不要把审计表复制到普通工单。

不要把生产联系方式复制进日志、表格附件、Issue、测试 fixture 或聊天记录。运营导出应最小化字段、限制接收人并设置删除时间。
